## What contradicts the contract

`test_read_op_reference` — the J1 row that proves a 1Password reference reads back —
can never run on Karl's machine. Its fixture gates and addresses 1Password in two ways
that do not match the account.

`tests/acceptance/secret_providers/conftest.py:107-118`:

```python
who = subprocess.run(["op", "whoami"], ...)
if who.returncode != 0:
    pytest.skip("1Password access not granted")
```

`op whoami` exits 1 on this machine while `op` itself is fully authenticated and
usable. The fixture reads that as "access not granted" and skips — so the gate is not
a gate. Karl, 2026-09-12: "NEVER run `op whoami`. That does not work. Testing
1Password is reading a value or querying it."

`conftest.py:120`:

```python
vault = os.environ.get("KSECRET_ACCEPTANCE_OP_VAULT", "Private")
```

There is no vault named `Private` in the account. Even past a working gate, the
`op item create` below it fails and lands on the second skip
(`"could not create a 1Password item in vault 'Private'"`). Both paths out of this
fixture are skips.

This is the failure the brief's own decision is meant to avoid: A3 accepts a skip when
*Karl declines to grant access*. It does not accept a skip that happens regardless of
what Karl does. The acceptance test that carries the `op://` half of J1 cannot go green.

## Why implementation stopped

Implementation did not stop; M1 is delivered as PR #32 and every other blocking row
passes. What stopped is the *verification* of one row, and the fix is not an
executor's to make: the fixture is a planner-authored acceptance test, and the CI
guard rejects `tests/acceptance/**` edits from `impl/*` by design. Editing it here
would be grading my own work on the one criterion I cannot otherwise satisfy.

Recorded so a planner session can repair the fixture rather than the skip being read
as A3 operating normally.

The provider itself is fine — verified by hand, 2026-09-12, against a real item in
`devops-ai-secrets-test` (the vault Karl created for this). Created with
`op item create --generate-password`, read back, deleted; the script compared values
in memory and printed only verdicts:

```

  stdout matches `op read --no-newline` exactly: True
  nothing on stderr: True
ksecret read op://…            exit 0, stdout "ok op://…", value absent from both streams
ksecret check op://…           exit 0, reports ok,        value absent from output
```

So this is a defect in the fixture, not in the milestone. What is missing is an
automated check that would catch a regression here.

## What triage needs to decide

1. **A gate that is not `op whoami`.** Karl: testing 1Password means reading or
   querying — e.g. `op vault list` (exit 0 on this machine), or simply attempting the
   `op item create` and skipping on *its* failure, which the fixture already handles.
   Whatever replaces it must distinguish "Karl declined" from "the query was wrong",
   or the skip stays ambiguous.
2. **The vault default.** `devops-ai-secrets-test` exists in the account for exactly
   this purpose; `Private` does not exist. `KSECRET_ACCEPTANCE_OP_VAULT` keeps its
   role as the override.
3. Whether the same gate shape appears in M2/M3's fixtures. `akv` gates on
   `az account show`, which is a real query — A2's shape looks sound; `bao` uses a
   container it starts itself.

## Planner resolution

**Classification: false fact.** The brief's J1 row stated that the `op://` test runs
when Karl grants access; the fixture's gate could not observe a grant, so the stated
fact did not hold of the code. Resolved on the planner side in spec PR #30, merged as
`5fd16d1`, without an amendment to what Karl signed — the jobs and the Surface are
unchanged; only the fixture's means of proving access changed.

What landed (`e36e973`, `68e69a4`, `9015edf`):

- **The gate is a real query.** `op_vault()` runs
  `op item list --vault <vault> --format=json` — which *is* the access prompt, so it
  doubles as the grant it waits on — and skips with the reason on a missing CLI, a
  timeout, or a non-zero exit. Both of this report's findings are addressed by the one
  change: no `op whoami`, and a vault that is actually queried rather than assumed.
- **The vault default is `devops-ai-secrets-test`**, the vault Karl created for this;
  `KSECRET_ACCEPTANCE_OP_VAULT` still overrides it. A2 now records the prerequisite as
  met.
- **The briefs separate a fixture's skip reasons from acceptable delivery evidence**, so
  a skip can no longer be mistaken for the milestone being proven.

Observed at head `a3a7f89`: **15 passed, 0 skipped** in the observer's independent run —
the `op://` row runs rather than skips, which is what this report asked for.

The hand verification recorded above stands as the first evidence that the provider
worked; the fixture is now what keeps it honest.
